# 衣橱间 · Wardrobe Studio

一个零付费接口、无需构建的个人衣橱网页。为 GitHub Pages 制作，使用原生 HTML、CSS 和 JavaScript，没有需要安装的运行时依赖。可选连接 GitHub 私有仓库同步。

## 独立穿着日记

导航栏「穿着日记」链接到 `wear.html`。主站只增加导航链接与适应新增入口的导航间距；不加载日记脚本，原 `app.js`、衣橱、搭配、档案册和数据结构保持原样。

- 日期视图：默认今天，周一开始的一周日期条，月历切换与过去日期补记；按日期勾选多件衣服，可从已保存搭配加入，备注选填。保存搭配本身不会产生穿着记录。切换编辑器日期会载入该日期原记录；取消、关闭或 Esc 不保存草稿。
- 单件记录：一键「今天穿了」、累计穿着天数与最近日期、单件月历。平时点日期只查看当天；进入「补记 / 编辑日期」后可跨月勾选多天，明确显示新增和移除数量，统一保存。
- 同一单品同一天只计一次。分别统计有记录的天数、不同单品数量、单品穿着天数合计，不把一天穿三件衣服误算三次穿搭。空白日期只表示未记录，未来日期不能手动记录。
- 新增、移除或修改有短暂撤销入口；保存失败保留编辑草稿与旧记录，支持重试。删除日记保留同步删除标记；已从衣橱移除的衣服保留名称与历史，统计中注明已移除。
- 日记使用独立 IndexedDB `wardrobe-wear-journal-v1`，日期与计数不写入衣物记录，图片只读取原衣橱。写入在同一事务里读取最新状态后修改，等事务提交才报告成功。原衣橱仍用原数据库。
- 复用用户此前选择记住的 GitHub 设备 / 会话授权；不另存授权。未记住授权时可本机使用，返回衣橱连接并记住设备后重新打开日记即可同步。新设备没有本机衣服时可从原私有仓库只读载入衣物资料与缩略图；已有本机衣服以衣橱当前内容为准。
- 日记仅同步私有仓库根目录 `wear-journal.json`，不修改 `wardrobe.json`、图片或搭配。三方合并按单品与日期去重，独立修改自动合并，冲突备注需逐条选择；分支并发变化重新读取后重试，绝不强制覆盖。已同步日记文件缺失、损坏或仓库不匹配时保留本机记录并拒绝写入。
- 日记提供自己的 JSON 导入 / 导出；导入只补充缺少编号，保留已有记录与删除标记。原「衣橱备份」格式不变，也不包含此独立日记；完整备份时分别导出衣橱和日记。日记导出不含衣服图片。
- 统计可查看本月、今年与全部时间，按穿着天数排序查看单品；所有统计只代表已记录内容。UI 为纸白、海军蓝，手机默认收起完整月历，保留周日期条。
- 验证覆盖日期与夏令时、去重、批量补记、保存失败 / 重试 / 撤销、共享衣服只读、独立备份、同步合并与并发、云端文件损坏保护，以及原有功能回归。尚未完成真实浏览器与手机视觉验收。

## 独立档案册

导航栏的「档案册」是独立阅读视图，原「我的衣橱」「搭配手册」与原单品弹窗保持原有版式。新视图使用 `archive-book.js` 与单独的 `archive-book.css`，共用当前衣物、附图与资料，不复制记录、不迁移数据，不需要再次上传。

- 桌面使用可收进左侧的竖排收录目录、右侧拼贴阅读区。目录默认折叠，仅保留左侧「展开目录」窄标签；可随时展开和收起，选中项有海军蓝标记；打开档案册默认显示全部衣服的收藏拼贴总览，所有单品在同一页连续展示，不分页截断。
- 每件衣服都拥有一组独立的收藏拼贴：服装实物主图始终为大图主角，旁边只展示本件档案里已保存的秀场图、参考图、细节或穿着附图。没有附图时只展示本件服装与简短文字，侧边留白，不借用其他衣服。点击服装打开该档案，点击附图放大查看完整图片、图注与来源。
- 总览采用杂志内页的十二列隐形网格：拼贴组以宽窄交替、上下错位的双列排列，窄屏转单列。主图根据服装轮廓保留修长或紧凑比例；附图在本组右侧以不同大小、少量叠放呈现，文字与收藏故事沿网格对齐。组间保留留白，不跨组重叠。全部已有附图均可查看，多于三张时侧边小图分两列排列。「全部收藏」返回总览，「单件档案」回到上次选中的单品。总览样式位于 `archive-wall.css`。
- 目录有独立搜索、品牌、秀场资料与故事筛选，价格默认隐藏。筛选同时作用于总览和单件阅读模式，空结果不显示上一个单品。上一件、下一件同步更新左侧选中项。
- 所有档案内页采用照片叠放的拼贴画布：大幅照片打底、前景印样覆盖、小幅细节插图、布标式品牌签，少量海军蓝图钉、原生 SVG 夹子与回形针。每三幅照片组成一页，超过三幅继续使用相同叠放版式；单幅照片也使用相同画布。每张照片仅出现一次，始终来自该单品。
- 单件档案采用紧凑阅读版式：桌面拼贴图幅受页面宽度和视口高度双重限制，标题、来源与故事位于右侧；窄屏上下排列，照片区域随视口缩小。完整长文字仍自然展开，附图续页同样限制图幅，点击照片可放大。
- 纸白、灰白、墨黑与少量海军蓝独立于主页配色，照片保留原色。流动的资料纸、完整收藏故事与来源放在照片画布下沿，不限定长文字高度。购入资料保留于可展开区域。未知年份不补填。
- 点击任一拼贴照片可通过原生对话框查看不受叠放遮挡的完整照片、完整图注和来源。拼贴内缩略图注可截短显示，放大窗口保留全文；图片仍由原有私有资产加载器提供。手机也保持照片叠放，不改为逐张竖排。
- 手机也默认折叠目录；展开后在拼贴上方显示可竖向滚动的目录。桌面展开时目录位于阅读区左侧，收起后拼贴使用释放出的宽度。目录切换不会重建照片、清空搜索或改变当前单品。
- 共用当前衣物、附图与资料；补充档案仍使用原编辑器，保存后保持该单品选中。修改名称或品牌不再匹配原筛选时自动清除筛选，继续显示刚保存的档案。原衣橱、搭配、存储与同步代码保持不变。
- 支持已有 PNG 纪念卡导出与加入搭配画布；导出价格需单独勾选。模拟 DOM/API 测试覆盖目录状态、筛选、共用编辑、附图完整性、保存失败与重试、自动同步、导出隐价、搭配入口及空状态。尚未完成真实浏览器及手机视觉验收。

## 已实现

- 批量上传 PNG、JPG、WebP、AVIF；单张最大 25 MB，一批最多 100 张。
- 名字选填，批量修改分类；根据文件名关键词建议分类，普通相机文件名归入“待整理”。此版本没有接入 AI 识图服务。
- 图片保持原比例、透明区域自动裁边、统一缩略图展示；可选去除与图片边缘相连的近白背景，保留原图，支持恢复。此工具并非人物服装分割或生成式修图，白色衣服和复杂背景需要检查。
- 单品档案：品牌、名称、配色、分类与细分类、款式、图案、尺码、原价、实际购入价与币种、全新或二手、原价/折扣/Sample Sale/礼物、购买渠道、购入日期、购入状态和备注，均可选填。点击图片或名称查看藏品卡，点击铅笔或“编辑档案”补充信息。
- 品牌下拉筛选与品牌输入建议；忽略大小写、重音和多余空格来合并品牌选项。搜索支持名称、品牌、颜色、细分类、款式、图案、尺码、购买渠道和备注。
- 衣橱价值：按已购入且非示例的单品汇总实际购入价与原价，显示价格记录覆盖数量；空价格不当作零元，明确记录的零元会计入。不同币种分别汇总，不自动换算。总额始终对应整个衣橱，筛选结果另显示实付小计。支持收藏与原图下载。
- 自由搭配画布：拖动、手柄缩放、大小和角度滑块、水平翻转、移至最前、自动排版、撤销。
- 草稿在本机自动保存；保存多套搭配，重新编辑，导出 1600 × 2000 PNG。
- 包含原图、单品、已保存搭配的 JSON 备份，以及验证后原子合并导入。相同编号保留本机已有记录，重复导入不会重复添加。
- 可选 GitHub 私有仓库同步：照片、完整档案与已保存搭配，按记录进行三方合并，冲突由用户选择。写入图片、元数据后使用非强制分支更新发布同一提交；网络中断或版本竞争不会报告同步完成。
- 云端图片按需加载，先用缩略图；编辑、搭配导出、下载原图或完整备份时再获取所需图片，并校验 SHA-256。原图保持不变，单张仍限制 25 MB。
- 8 件可选示例插画，可以统一移除。示例默认不会添加。
- 手机、平板与电脑布局；键盘操作、表单标签、减少动画设置。

## 在 GitHub Pages 发布

1. 在 GitHub 新建一个 **Public** 仓库，建议名称 `wardrobe-studio`。GitHub Free 的 Pages 使用公开仓库。
2. 把本目录中的文件上传到仓库根目录，确保根目录里有 `index.html`。不要把整个 `wardrobe-studio` 文件夹再套一层上传。
3. 进入仓库 **Settings → Pages → Build and deployment**。
4. **Source** 选择 **Deploy from a branch**；选择 `main`、`/ (root)`，保存。
5. 等 GitHub 显示发布成功，打开其提供的网页地址。项目通常位于 `https://<GitHub用户名>.github.io/wardrobe-studio/`，实际以 Pages 设置显示为准。

不需要购买域名、配置 API key、安装 Node.js 或运行付费模型。文件使用相对路径，也可以放入已有网站的子目录。

## 本机预览

在本目录执行：

```bash
python3 -m http.server 8000
```

Windows 安装 Python 后也可以使用 `py -m http.server 8000`。然后访问 `http://localhost:8000`。本机预览和 GitHub Pages 使用不同地址，因此各自保存自己的衣橱。迁移时请导出并导入备份。

## 数据和备份

- 未连接 GitHub 时，上传图片和记录保存在当前浏览器的 IndexedDB。连接私有数据仓库后，照片、单品和已保存搭配会按同步设置上传 GitHub；本机保留缓存。
- 不同设备连接同一私有数据仓库后，可加载同一份衣橱。开启自动同步会在保存后提交；查看另一设备刚刚保存的内容时可点“立即同步”。未连接时可用完整备份迁移。
- 清理网站数据、无痕模式、浏览器存储回收、设备故障可能导致记录丢失。请定期导出备份。
- 新增档案字段会随 JSON 备份导出、恢复；旧版备份仍可导入，缺少的选填信息默认为空。购入状态默认为“已购入”，币种默认为英镑。已有购入价格继续作为实际购入价；新增原价、全新/二手和购入方式默认未记录。
- 备份包含原图。请自行保存到安全的位置，不要提交到公开仓库。
- JSON 备份目前限制 500 MB；图片以 base64 编码，备份会大于原图文件总大小。大衣橱后续可升级为压缩归档。
- 备份包含已经按下“保存搭配”的记录。画布草稿仅在本机自动保存，导出备份前请先保存想保留的搭配。
- 删除单品会一并删除它的本机图片，并从已保存搭配中移除对应图层。移除示例只影响示例和搭配中的示例图层。
- 图片原图保留；展示图最长边缩至 1800 像素。导出搭配不代表真实尺码、上身效果或虚拟试穿。

## 连接私有 GitHub 数据仓库

1. 数据仓库须为 Private，并至少有一份 README 来初始化默认分支。网站本身继续由公开的 Pages 仓库托管。
2. 在 GitHub 创建 Fine-grained personal access token，仅选择此数据仓库，Contents 设为 Read and write。不要授权整个账户或提交授权凭据到仓库。
3. 在网页“GitHub 同步”中填写用户名、数据仓库和授权，点击“连接并合并衣橱”。当前本机与云端记录会合并；同一记录双方均修改时要求选择。
4. 默认授权只在页面内存中使用。用户明确勾选“记住此设备”后，授权保存在此浏览器的 localStorage，下次打开自动连接；取消勾选或断开连接会清除。仅在自己的设备和普通浏览模式中使用。授权到期、被撤销或浏览器清除网站数据后需重新输入。授权不写入 IndexedDB、JSON 备份或源代码。旧版 sessionStorage 授权继续在原标签页内有效，不会自动转为设备记忆。
5. 看到“已同步”才表示该次 GitHub 提交及本机同步检查点均完成。离线、更换授权或同步失败时，本机修改保留为待同步。

同步元数据位于 `wardrobe.json`，图片使用 `images/<单品编号>/<SHA-256>.<扩展名>`。照片、档案和已保存搭配同步；未保存的画布草稿仍在本机。GitHub 会保留提交历史，因此删除当前单品不等于清除历史提交中的文件。

测试使用模拟 GitHub API 与模拟 DOM，覆盖图片上传/校验、私有性检查、空衣橱、跨设备合并、冲突、授权失效、并发分支更新、缓存、导出和授权存储。未通过自动测试声称完成真实个人授权；首次连接须由仓库拥有者完成。


## 藏品档案与纪念卡

- 点衣服图片或名称查看档案；原来的 ＋ 按钮继续用于加入搭配。
- 编辑档案可记录系列年份、季节、系列名称、Look 编号、秀场同款/秀场实穿、待确认/已确认、HTTPS 来源链接和最多 3000 字的收藏故事。
- 每件最多 12 张附图，区分秀场、实物细节、穿着和参考图，可附说明与来源；支持 PNG/JPEG/WebP/AVIF，每张输入不超过 25 MB。附图按最长边 1800px 整理后保存，主图的原图仍独立保留。新增与移除附图在“保存档案”后生效。
- 档案页完整浏览相册；导出 PNG 纪念卡使用主图与首张秀场图（无秀场图时取首张附图），保留系列、故事、来源和购入记录。默认隐藏价格，可主动勾选显示。
- 相册图片通过原有校验、不可变文件路径和原子 Git 提交同步；本机保留按需缓存。JSON 备份包含全部附图与档案。
- 新云端数据和备份使用 version 2，读取兼容 version 1。旧版本网页会拒绝 version 2，避免静默丢失附图；手机与电脑均需刷新到新版后再同步。
- 自动测试使用模拟 DOM/API 和 Canvas 绘制调用，覆盖保存/取消、同步、删除、备份恢复、价格隐藏和长文本布局；未进行手机实机或浏览器视觉验收。

## 手机图片加载恢复

- 页面隐藏时保留仍被页面使用的对象 URL，返回页面或切回可见状态时重建图片视图，避免移动端页面缓存继续引用已撤销的地址。
- 使用与衣橱清单一致的私有 GitHub JSON/base64 下载路径，验证 SHA、声明大小、编码与 SHA-256 后再生成图片 Blob。
- 图片由一个加载策略调度；解码失败时尝试新对象 URL、主图和重新校验下载，次数有上限。失败时显示同步重试提示，保留已有照片与记录。
- 新增模拟页面生命周期与解码错误的回归测试。真实 iOS Safari 的显示结果仍需手机确认。

## 档案保存反馈

- 来源同时支持文字说明与 HTTPS 网址，未带协议的完整域名会补全 HTTPS；纯文字来源以文本展示，不作为链接执行。
- 编辑表单使用应用内校验，保存错误直接显示在弹窗内的保存按钮上方，避免浏览器校验或弹窗层级让失败看起来没有响应。
- 校验与本机存储失败保留编辑内容，可修改后重试；成功提交本机事务后再关闭编辑窗口、打开档案卡。保存不等待 GitHub 网络同步。
- 本机写入失败时，对照已保存的云端图片引用核对 MIME、大小与 SHA-256，仅跳过有相同云端副本的图片缓存后重试整个事务。新附图、未同步的替换图、无法读取或核对的图片均保留；不删除 GitHub 图片，不清空浏览器数据。同步检查点与档案仍在同一事务中提交。
- IndexedDB 请求错误会保留具体错误名称，等待事务中止后才报告失败；只有 `QuotaExceededError` 才提示存储空间不足。模拟测试覆盖 Blob 写入失败后保存、跨设备同步，以及重试失败时保留编辑内容；真实 iOS 的恢复结果仍需实机确认。
- 保存后打开的只读档案卡不再阻挡自动同步；编辑窗口与其他操作弹窗仍会推迟自动同步，避免覆盖尚未保存的输入。档案卡内显示本机保存、等待同步、同步中、已同步或失败状态；同步后更新卡片，保留相册位置与价格显示选项。

## 本机图片字节存储

- IndexedDB v2 将主图、缩略图、原图与附图写成带 MIME 的 ArrayBuffer，读取时重建 Blob，避免手机端的 Blob/File 写入错误。旧记录仍可读取，在下次成功写入时转换；转换全部完成后才开启写入事务，任一图片读取失败均不提交档案或同步检查点。
- 对已验证下载、已完成同步准备，或来自干净的原子同步检查点的缓存，使用当前内存对象与云端引用绑定作为恢复凭据。缓存读取失败时可从原私有仓库重新校验下载；未同步替换图与无法证明来源的图片不自动覆盖。
- 更新时关闭旧衣橱标签页，再打开新版本。旧版数据库写入器不能打开 v2，避免把字节记录误当图片后覆盖。若回退页面，必须保留 v2 的读写兼容层。不会清除网站数据。
- 测试覆盖原始图片字节与附图重开一致、旧 Blob 兼容、转换失败时不创建事务、旧缓存恢复后保存并同步新附图，以及不覆盖未同步图片。仍未进行 iPhone 实机验收。

## 拼贴实验（独立页面）

- `experiment.html` 提供随机选衣、锁定单品、只换构图、添加衣橱单品、人物／脸部／参考图上传、自由拖动及位置、大小、角度、翻转、透明度和层级调整。主导航与搭配区有独立入口；从搭配区进入时带入并锁定现有画布单品。可撤销调整。
- 这是本地规则随机与画布合成，不调用付费生成接口，不模拟上身，不自动抠图。保留图片本来的颜色和比例，透明图片沿轮廓加纸白边，背景使用少量灰蓝、灰粉或灰绿半透明纸张与海军蓝回形针。
- 只读共享衣橱。无本机衣物时可复用用户已记住的 GitHub 私有仓库授权，读取远端元数据与图片；缩略图按需加载，最多并行 3 张。不会提交实验素材到公共代码仓库，也不写入衣橱、档案或穿着日记。
- “附图”仅使用该衣服自己的秀场／参考照片。没有附图的衣服不会被配上其他藏品的照片。空衣橱可明确选择示例素材，不会伪装成私人衣服或导入原衣橱。
- 实验使用独立 IndexedDB `wardrobe-collage-lab-v1`，上传图先转成 ArrayBuffer 再开启写入事务，成功提交后才反馈已保存。保存的实验仅在当前浏览器；可导出 2000×2500 PNG 留存，导出会等待全部图片成功解码，失败则保留编辑并显示错误。随机生成后另存为新实验，继续调整已打开的实验会更新该实验。
- 自动化检查：`node --test tests/*.test.cjs`。新增锁定、随机选择、比例、旋转命中、搭配入口、只读隔离、同衣服附图、保存失败、空衣橱、导出失败、事务完成与独立页面资源检查。当前环境无法运行浏览器视觉验收，手机实际显示与下载行为仍需设备确认。

## 衣架浏览（独立、零预算）

- `rack.html` 读取原衣橱，新增导航入口。基于照片的 CSS 透视排列，支持鼠标／触摸横向拖动、轻微阻尼摆动、前后切换、键盘方向键、Home/End、单件放大以及原档案跳转；支持品牌、分类和文字组合筛选。
- 使用原有照片，不生成真实服装网格、背面或布料褶皱。无付费组件、AI 接口或外部渲染库。照片背景保留；透明背景正面图展示更自然。配饰也按现有图片显示。
- 本页只读 `suzy-wardrobe-studio-v1`。记住设备的 GitHub 私有仓库授权可在新设备读取远端元数据及经过原云端校验器验证的图片。不会写回图片缓存、搭配、档案或日记；不会把授权或私人衣服提交到公共代码仓库。只有「减少动态」的显示偏好保存在本机。
- 仅在舞台挂载当前附近最多 12 件衣物，图片最多并行读取 3 张，解码失败可尝试原主图或同来源云端图片；错误保留原衣物记录并提供重新读取入口。摆动停下后停止动画帧，切到后台时暂停；支持系统减少动态和手动开关。
- 空衣橱可明确选择示例体验，示例只在此页内存中。单件弹窗读取实际品牌、尺码、颜色、价格和收藏故事；「打开原档案」用单品 ID 跳转到原衣橱，等待该记录就绪后打开一次，包含自动同步后才出现的记录。
- 验证：`node --test tests/*.test.cjs` 共 127 项通过。浏览器已检查桌面、390px 窄屏布局、示例衣架、鼠标拖动和放大预览。窄屏预览不等于真实 iOS Safari 触摸验收。

- 鞋履从悬挂轮播中独立出来，集中陈列在下方单行鞋架，支持横向滑动、同品牌／分类／搜索筛选、单件预览和原档案跳转。鞋履预览不显示衣架；筛选仅有鞋履时隐藏空的悬挂区域。新增混合衣橱、纯鞋履衣橱与鞋履预览切换测试。

- 手机触摸修复：仅在衣架区域自身丢失 pointer capture 时结束拖动，忽略从衣服按钮转交隐式 capture 时冒泡的丢失事件，防止横向手势被提前取消。保留纵向页面滚动和双指缩放，忽略额外手指抢占；新增触摸 capture 转交的复现与回归测试。实际 iOS Safari 尚需手机确认。

- 衣架视觉适配：在本机对已解码图片的透明轮廓取样，估算肩部或肩带支撑宽度，衣架与图片按同一比例排布；细肩带使用窄衣架、裤裙使用夹式、包袋与配饰使用小挂钩。衣架展示与单件放大同步适配尺寸，不改动原照片或衣物记录。不透明背景图片采用保守的比例回退；轮廓估算不等同于服装结构识别。

### 衣领自动估计与校准
衣架页面按透明图上边缘的凹口估计领口；不透明后领或不确定轮廓采用贴近图片上缘的小段木臂，不再默认完全隐藏；手动选择高领时仍可隐藏木臂。单件预览中的「校准衣领与衣架」支持圆领、V 领、高领、三个拖动点和位置/宽度/深度滑杆。校准可预览、取消、保存或恢复自动；数据按衣服 ID 单独保存在当前浏览器的 `wardrobe-rack-neck-v1`，不改动衣橱、图片或 GitHub 私人数据，不跨设备同步。替换衣服图片后可重新校准。该功能是轮廓估计，不是 AI 领型识别。

衣架浏览中的上装、外套、连衣裙使用依据用户参考图重绘的双兔木雕衣架素材 `assets/rabbit-hanger.webp`。原始图由内置图片生成工具制作，网页使用压缩 WebP；肩部保持图像原比例，领口区域沿用自动估计和单件校准遮挡，裤裙夹式衣架与鞋履排保持原有逻辑。
